PHA-946: "Compare page not calculating some incorrectly. Ty's picks not highlighted. He has MIBR." Screenshot showed Ty's MIBR struck-through (miss) in the 3:1/3:2 ADVANCED bucket even though MIBR advanced and showed green ✓ for the other player.

**Root cause:** compare grid + THE STEAL reel matched each pick against the winner in its EXACT slot index. But within a Swiss bucket (3:0 / advance / 0:3) the slots are interchangeable — `scoring.ts` already judges them as set intersections per bucket ([[phatt-picks-pha918-live-leaderboard]] PHA-918). A correct pick sitting in a different slot row than its winner read as a miss → grid disagreed with the score. SAME bug class as PHA-900 follow-up#3 (consensus keyed per exact slot vs bucket-grain, see compare redesign memory).

**Fix (PR #50):** added two pure shared helpers to `src/lib/swiss-bucket-core.ts` — `resolveBucketWinners(slotIndexes, outcomes)` → `{winners:Set, fullyResolved}` and `bucketPickState(pick, winners)` → `hit|miss|pending|empty` (hit if team in bucket winner-set; miss only once fullyResolved; pending until then; `0`/undefined = empty). Compare page (`src/app/(app)/leaderboard/compare/page.tsx`) routes BOTH grid hit/miss AND steal detection through them. Playoffs collapse to one single-slot bucket per match → strict per-slot preserved (single-slot bucket is provably equivalent to old playoff tileState). Steal = "you hit a team opponent never picked in scope" (bucket for Swiss, slot for playoffs). Deleted old per-slot `tileState`.
