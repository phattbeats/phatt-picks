# Deep Repo Audit — 2026-06-13 (PHA-1015)

Full dead-code + bug audit of phatt-picks (136 source files / ~27.5K LOC). Findings
were produced by five parallel subsystem auditors and the top items were re-verified
by hand against source. Severity: **P0** = wrong scores / leaked picks / outage,
**P1** = wrong data shown to users, **P2** = resilience / latent / multi-major path,
**P3** = minor / hardening.

The recurring failure mode in this codebase is **silent data divergence** — a parse
or grain mismatch shows wrong/missing data with no surfaced error. The two highest
findings are both that class.

---

## P0 — Reveal page strikes correct Swiss picks as misses

`src/app/(app)/reveal/[section]/page.tsx:240-247`

The per-pick breakdown cards judge every Swiss pick **strictly per slot**
(`isCorrect = pickId === winner` at the same `slot.index`), but the authoritative
scorer (`scoring.ts`) and the compare page judge Swiss buckets as **sets** (PHA-918 /
PHA-946). Within a Swiss bucket the slots are interchangeable, and the clinch resolver
(`swiss-clinch-core.deriveClinchedSlots`) fills winner rows in **layout order, not
pick order** — so a player who nailed both 3:0 teams in swapped slots sees both cards
render ✗.

The same page's header (`correct`, line 203) comes from set-based `scorePlayer`, so the
header count and the cards **contradict each other** on the same screen. The per-slot
`slotStats` consensus/bold calls (lines 128-146) inherit the same grain error.

**Fix:** route Swiss-section cards + consensus through `resolveBucketWinners` /
`bucketPickState` (mirror compare/page.tsx); playoffs stay per-slot.

## P1 — Player profile accuracy strikes correct Swiss picks as misses

`src/app/(app)/players/[id]/page.tsx:156-170`

Same root cause as the P0. The accuracy stat loops `gPick[slot.index] === winner`
per exact slot. Headline Points/Rank (from `scorePlayer`) are correct; only the
Accuracy card lies. **Fix:** derive correct/resolved from `scorePlayer().bySection`
(`correct`/`possible`), keeping playoffs per-slot.

## P1 — team-stats matches crawl results to teams by raw URL, falls back to position

`src/lib/team-stats.ts:169-176`

`crawlChunk` keys results by exact submitted URL, then falls back to `targets[i]`
positional index when crawl4ai returns a redirect-normalized or reordered URL
(`semaphore_count` concurrency makes order unstable). A mismatched chunk assigns one
team's last-5 markdown to another team's `pickid` — wrong dossier, no error.
**Fix:** parse the HLTV team id out of `r.url` (or the page's own profile link) and
match by id instead of exact-URL equality + positional fallback.

## P1 — Standings bracket-vs-table parse asymmetry stalls outcome bridging

`src/lib/swiss-results.ts:229-247,379` + `src/lib/outcomes.ts:320`

`ingestStandings` persists if **either** the W-L table or the bracket parsed, but
`getSwissStandings` returns `null` when `rows.length === 0` even if a full bracket is
present, and `bridgeSwissOutcomes` resolves leaderboard outcomes **only** from
`getSwissStandings().rows`. If HLTV reformats the table header (`HEADER_RE` anchors on
the literal `Group Swiss … Record`) while the bracket still parses, the leaderboard
**silently stops resolving Swiss clinches** — the exact PHA-918/951 "scoring froze for
two days" symptom. **Fix:** fall back to deriving records from the parsed bracket's
terminal advancing/eliminated lists; don't null standings when only the table missed.

## P1 — CSRF: `GET /api/auth/logout` lets a third-party page log users out

`src/app/api/auth/logout/route.ts` + `src/lib/session-core.ts:82-90` (SameSite=Lax)

Auth is cookie-only with no CSRF token / Origin check; the sole defense is
`SameSite=Lax`, which does **not** block top-level GET navigations. `<img
src=".../api/auth/logout">` on any page logs out a visiting user. **Fix:** make logout
a POST (or check Origin), add an Origin/Referer allowlist to mutating routes.

## P2

- **`HEADER_RE` / `STATS_RE` standings parse is unbounded** — `src/lib/swiss-results-core.ts:103-135`. `STATS_RE` greedily binds the first `N N N ±N N-N` run on a row; a map score like `13-7` in the cell can be read as wins=13/losses=7 → "advanced". No validation that wins/losses ≤ Swiss bounds. **Fix:** validate `wins/losses` in range and `matches === wins+losses`; drop rows that fail.
- **`ACTIVE_EVENT_ID` bound at module load** — `src/lib/events-core.ts:355,363`. Every page importing `ACTIVE_EVENT_ID` pins it for the whole process lifetime; when Cologne archives and a next Major goes live without a redeploy, the dashboard serves the stale event. **Fix:** call `currentEventId()` per-request in the `force-dynamic` RSCs.
- **`selectCurrentEvent` upcoming ranking mixes lead-adjusted go-live with raw start** — `src/lib/event-lifecycle-core.ts:133-143,249-252`. Between Majors, can count down to the wrong upcoming event. **Fix:** sort upcoming by `min(goLive, dates.start)`.
- **`firstLockMs` returns +Infinity for unparseable start + no schedule** — `src/lib/event-lifecycle-core.ts:140`. A misconfigured future Major silently never goes live. **Fix:** add `dates.start`/`dates.end` parse validity to `validateEventRevealConfig` (CI guard).
- **Avatar route runs regex before length cap** — `src/app/api/avatar/route.ts:33-38`. Full attacker body buffered + regex-scanned before the 64 KB check. **Fix:** length check before regex; cap body.
- **`/api/push/test` has no rate limit** — self-targeted push amplifier. **Fix:** per-player cooldown.
- **prelock reminder tick is O(stages × subscribers) DB queries** — `src/lib/prelock-reminders.ts:130-145` (`pick.count` per subscriber). **Fix:** one `groupBy` over `Pick`, filter in memory. (Low impact today: ~0 subscriptions.)
- **crawl4ai auth inconsistency** — team-stats sends `Authorization: Bearer`, standings sends none (`swiss-results.ts:154-168`). If crawl4ai ever requires the token, the user-visible standings crawl 401s while team-stats works. **Fix:** shared crawl helper / same headers.

## P3

- `bridgeSwissOutcomes` uses `Date.now()` while the rest of the read path threads the request clock (`outcomes.ts:273-316`) — clock drift across the gate set near a lock boundary.
- Liquipedia in-process throttle is racy (check→wait→stamp instead of atomic claim) — `liquipedia.ts:64-71`. Dormant (slotMapper returns null).
- `LiveSwissBracketBoard` uses array index as React key for blank→match transition rows — `LiveSwissBracketBoard.tsx:190-202`. Can reuse stale DOM as cells resolve live.
- `MajorsPage` conflates "score unavailable (non-live layout)" with a genuine 0 — `majors/page.tsx:103-156`. Latent until a 2nd Major archives.
- `AutoRefresh` bursts `router.refresh()` on every visibility toggle, unthrottled — `AutoRefresh.tsx:30-39`. Redundant server work, no leak.
- `decryptAuthCode` doesn't length-guard the decoded buffer (`crypto.ts:26-34`); `getClientIp` trusts `X-Forwarded-For` for the IP account cap (`auth/local/route.ts:48-55`); captcha + middleware fail **open** when secrets are unset — fragile given this app's history of Force-Update env drift.
- Consensus `pct` rounds per-share so bars can sum to 99/101% (`consensus-core.ts:73`) — cosmetic.
